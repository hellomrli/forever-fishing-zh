## 额外完善

- 图标缩图时保留至少 12 像素细节，支持小尺寸图标。
- 水花候选结合自己浮漂周围的画面变化确认；局部画面之外的变化不会进入该核对区域。
- 手动框选识别范围，寻找和跟踪遵守保存的窗口比例范围。
- F8 / F9 默认全局控制，通过独立 Windows 消息线程接收，再在 Tk 线程执行操作；避免 Tk 消息循环吞掉快捷键。
- 进程捕获在真正打开时探测；失败时自动系统回环，显示实际设备与原因。
- Windows 系统回环增加读取线程 COM 初始化和多声道混音，避免单声道采集异常。
- 音频断开有限次数重连；空读取不会错误清零重连预算。
- 长录音流式写入 WAV；短录音分析返回明确结果。
- 校准、录音、截图预览任务可以取消；匹配过程会在每次匹配之间检查取消。
- 中文 Windows 路径图片读写、设备刷新、日志限制和导出、配置备份恢复。
- 独立 GitHub 项目、原生 Windows PyInstaller 打包、生成 EXE 后的真实 GUI 自检、便携 ZIP 与 SHA256。

| 改动 | 使用效果 | 验证 |
| --- | --- | --- |

| 修正阈值背景估计 | 按得分峰值所在帧排除已识别水花，避免把水花本身计入背景噪声 | 起始时间与峰值帧相距较远的合成录音得分 |

本轮 Linux / CPython 3.12.16 验证：**89 项回归测试通过**（包括 7 项发布元数据检查），Ruff 检查与格式检查通过。真实 Tk 自检覆盖 900×640 窗口、100% / 125% / 150% 字体缩放，以及设备切换时的等待提示、自动继续和停止按钮。

使用同一段 60 秒、22050 Hz 合成噪声叠加两次内置水花，在两个独立进程中比较旧实现与新实现（NumPy 2.5.4）：分析进程峰值 RSS 从 **332.13 MiB 降到 65.72 MiB**，减少 **80.2%**；所有得分的最大绝对差异为 `1.19e-7`。单次处理耗时分别为 3.949 秒和 2.772 秒，耗时会随硬件和负载变化。

本地验证报告写入 `checks/tests.xml`、`checks/lifecycle-gui.json` 和 `checks/audio-analysis-benchmark.json`。界面自检可重新执行：

```bash
xvfb-run -a uv run python -m wowfish.gui.launcher --smoke-test checks/lifecycle-gui.json
```

Windows 原生构建和生成 EXE 自检由 v1.0.1 的 GitHub CI / Release Windows 工作流执行，全部通过后发布。真实 Forever 客户端联调仍未执行。暂停检查和分析取消在等待片段、计算批次之间生效；底层截图、音频驱动的单次调用仍会影响资源关闭时间。

## 验证边界

单元回归使用内置素材、合成图像、合成音频和模拟游戏输入，不发送真实游戏按键。
Windows EXE 自检打开真实 Tk 窗口，在自己创建的中文测试窗口上检查原生枚举和截图接口，验证快捷键消息分发、配置与布局。

这些验证可以证明源码回归覆盖、Windows 打包和界面流程可运行，不能代替实际 Forever 游戏客户端联调。
客户端交互能力、UI 皮肤、水面动画和声音设备差异，仍可能影响图标与咬钩识别；画面确认的目标是降低误触发，而不是保证能区分所有相邻浮漂。

校准取消会等待当前单次 OpenCV 匹配返回；具体停止延迟也受当前系统截图和音频驱动调用影响。
发布 EXE 没有做 Authenticode 签名，SHA256 文件用于核对下载完整性。
